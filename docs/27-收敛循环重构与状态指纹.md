## 1. 收敛循环：先定点，不行再重写，还不行就停下等人（B-12）

作者定的顺序。旧版只有「整章重写 ≤3 轮」，问题是**不可控**：
模型会把没问题的段落一起改写，上一轮刚过闸的地方被改坏，「改一处、坏两处」，
循环空转烧 token，最后停在 `max-rounds`——一个与「问题不大」同形的名字。

新版三段：

| 阶段 | 上限 | 做什么 |
|---|---|---|
| 定点修订 | 2 轮 | 按 finding 的 `quote` 定位到正文那几句，**只改它们**，其余段落一个字符不动 |
| 整章重写 | 1 轮 | 定点改不动（引句全没命中 / 超改动量 / 输出无法解析）才升级 |
| 停下等人 | — | `stopped: 'human-needed'` + `handoff` 交接清单（含引句），退出码 3 |

定点修订的三条守卫，每条对应一类真实翻车：

1. **引句定位不到 → 跳过并报出原因**（复用 B-11 的防幻觉纪律）。
   定位先逐字找，失败再去空白回映射；但**返回的必须是正文里的真实区间**——
   替换得作用在真实区间上，不能拿模型给的那串字面量硬套。
2. **替换文本为空 → 跳过**。模型返回空串的意图可能是「删掉这句」，
   而静默删正文不可逆；要删得由人来做。
3. **改动量有上限**（条数 ≤12 且替换字符 ≤全文 50%）→ 超了整批放弃并如实报告：
   那已经不是「定点」而是「重写」，该走重写那条路，不该伪装成定点。

另：区间重叠的补丁只保留先出现的那条，另一条记为跳过。

**失败姿态**：定点修订的 `parse` 失败**不整轮中断**——那会把一次「格式没对上」
升级成整章失败，而机械 gates 明明还能用。只记为「0 补丁」并升级到整章重写。
`config`/`timeout`/`http`/`circuit-open` 才是真故障，记下即停。

### 顺带落掉 B-63：Judge 与 gates 的合并语义

**不合表，只合「决策输入」。** 两者不查同一项（M10.5），所以各自落各自的盘
（`gateStatus` / `judge.json`），循环时取**并集**当拦截集。信息不丢、口径不混。

原先的顾虑（B-63）是「怎么合起来判能否提交」；答案是：不需要合成一个字段，
只需要在**做决定的那一刻**把两边的问题都拿出来。落盘保持分开，
是因为分开才有信息，合并只会在下一次「到底是谁没过」的追问里失效。

## 2. schema v2：指纹从 mtime 换成内容指纹（B-13）

mtime 两个方向都会骗人：

- **假过期**：git checkout、复制文件都刷新 mtime，内容没变却让结论作废
  （v1 的注释自己把这条记为「已知弱点」，代价是白跑一遍检查器）。
- **假绿**（更危险）：同一时间粒度内的改动可能 mtime 不变，
  于是「内容变了结论还挂着」——那正是过期清扫要防的东西。

改动要点：

- 新增 `packages/core/src/hash.ts`：**全项目唯一一份** `contentHash`。
  `plan.ts` 原有的 `hashText` 改为转调它。三处（plan 签字 / gateStatus / 判据结论）
  各写一份必然漂移——本项目吃过多次亏的模式，这次先掐掉。
- `GateStatus.checkedMtimeMs` → `checkedHash`；`judge.json` 同步改。
  **两个指纹机制必然漂移，所以判据结论也用同一个。**
- `readState` 的清扫改成「刷新指纹 + 判过期」一步做。
  分两步会留下「gateStatus 是对的，但 contentHash 是旧的」这种半真状态，比全错更难查。
- 新增 `SCHEMA_VERSION = 2` + `migrateV1ToV2`：v1 能读进来，但 **gateStatus 一律丢弃**。

### 为什么迁移要丢弃 v1 的绿（而不是「mtime 还对得上就保留」）

v1 的绿是用 mtime 判的，而 mtime 正是要废掉的信号。拿它来给 v2 的绿背书，
等于把「不可靠」原样带进新格式，只换了个字段名。
代价是每本书重跑一次 `novel gates --write`；本项目的取舍一贯是
**「过期的摘要不如没有」**。

### `stripGateStatus` → `stripConclusions`

`needsReview` 也是**结论**（「有人判定过这章要人看」），从 `novel state --set`
写进来就能伪造「这章已经人看过了」。所以净化范围扩到它，函数名一并改——
名字不改就会撒谎。

## 3. 退出码契约（B-14）

```
0 = 正常跑完。**结论只看 stdout 的 JSON**——findings 几条、严重度如何，与退出码无关。
1 = 脚本崩了（未捕获异常）。本次没有结论。
2 = 环境/配置错（书配置缺失/读不了/结构非法）。本次没有结论。
```

★非 0 的含义只有一个：**本次没产出可用结论**。一律当失败处理，
绝不允许读成「查了没问题」。

- **Python 侧**：`kit.py` 新增 `EXIT_*` 与 `emit_error` / `fail_config` / `run_main`。
  三处 `sys.exit(2)` 改为 `fail_config`，**除 stderr 外 stdout 也吐结构化原因**。
  为什么要给 stdout：上层要能按 kind 分流（配置错 → 作者改 book.json；崩溃 → 报 bug）。
  只给 stderr 的话上层只能拿到一坨文本，分不出这两件事。
- **TS 侧**：`GateFailureKind` 增加 `'config'` / `'crash'`。
  `'config'` 与 `LLMError` 的词汇表**同名**——「统一」二字指的就是这个：
  两条外部调用线（LLM HTTP 与 gate 子进程）失败词汇一致，日志/告警/grep 才能跨线对齐。
- **失败关闭守卫** `assertNoResultOnFailure`：非 0 退出但 stdout 里有完整 GateResult
  → 当场报契约违规。退出码说「没跑成」、stdout 说「跑成了」，两边矛盾时
  **拒绝挑一个活下去**——静默丢掉 findings 就是「查了没问题」同形。
- **CLI 退出码**按 v0.2 M16 统一：顶层 catch 从 1 改为 **2**。
  0 成功 / 1 内容未通过 / 2 环境或参数错误 / 3 需要人工介入。
  走到 catch 的从来不是内容结论，混用 1 会让调用方分不清「稿子没过」与「命令敲错了」。

## 4. 测试基建（B-15）

### P2-1 CLI 子进程冒烟（8 项）

补的洞是：**函数测过了，但「CLI 真的调用它」没测过**。
docs/23 自承 `stripGateStatus` 只测了函数、没测接线——而「守卫在但零调用者」
正是本仓反复栽的形态（`style_doc_issues` / `hook_check` / `checkPlanGate` 三次同源）。
**core 的单测永远测不出这件事：接线在 `apps/` 这一层。**

所以一律起真子进程跑 `dist/index.js`，断言只看退出码 + stdout 的 JSON。
最要紧的一条：伪造一枚「能存活过期清扫」的绿（`checkedHash` 取真实内容指纹）
走 `state --set`，断言 CLI 真的把它摘掉了。

### P2-2 gates 检查器固件（9 项）

★**用标准库 `unittest` 而不是 pytest。** 本机 `python -m pytest` 报
`No module named pytest`，而本仓没有 Python 打包设施。引入 pytest 就多一步
「先 pip install」——那一步一定会被忘记，然后固件变成「文件在但从不运行」的死重量。
本项目 2026-09-25 刚栽过一次同源的坑（硬编码测试清单）。

每个检查器**至少一正一反**——只测正例等于只证明「它没崩」，不证明「它有牙齿」。
另钉住一条设计意图：`style_doc_check` 恒 `chapter_count=0` + `scope=book`，
即**不许接到回填上把全书刷绿**。

固件经 `packages/core/test/gates-python.test.ts` 接进 `pnpm -r test`：
只靠「记得手动跑」的话它等于不存在。缺 Python 时**跳过而非假绿**
（汇总里会留下 `# skipped N`，「环境没有」与「跑了且通过」形状不同），
并断言条数 ≥9——被静默删掉就是回归。
