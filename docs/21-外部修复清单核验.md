### P0-2 —— 成立，但机制与键名都要改

**清单成立的部分（且已实测证实）**

`novel init` 生成的 `book.json` **完全没有 `checks` 段**。而 `kit.py:284` 的 `sec()` 对缺失段返回 `{}`：

```python
def sec(self, name):
    v = self.cfg.get(name)
    return v if isinstance(v, dict) else {}
```

于是 `consistency_check.py` 里五个可选机检项**全部静默跳过**：

| 机检项 | 触发条件 | 缺失时的行为 |
|---|---|---|
| `checks.rhythm` | `if not R or not R.get("enabled", True): return []` | **跳过** |
| `checks.panel` | `if P:` | **跳过** |
| `checks.hook_check` | `if not H or not H.get("enabled", True): return` | **跳过** |
| `checks.foreshadow_check` | 同上 | **跳过** |
| `checks.name_roster` | `if not R or not R.get("enabled", True): return` | **跳过** |

**实测 A/B（同一章，328 汉字，全由 5 字短句构成）**

| 配置 | 机检结果 |
|---|---|
| A：`book.json` 原样（无 `checks`） | `严重 0 · 中等 0 · 轻微 0`，`findings: []` |
| B：注入 `checks.rhythm = {narr_avg_min:12, …}` | `严重 3`，全部为「句长节奏」 |

→ **防线确实是关的**，且关的方式是「配置缺失」，不是「显式 false」。

**清单判错的部分**

1. **机制描述错**：清单说「三个开关全是关的」，实际是 `checks` 段整体不存在。
   这个区别有后果——写默认值时要**新增整个 `checks` 对象**，不是「把 false 改成 true」。

2. **键名错，且错法会导致静默失效。** 清单示例：

   ```jsonc
   "panel": { "enabled": true, "max_entries": 4 }   // ← 两个键都不对
   ```

   真实 schema（`kit.py:412-424` 校验、`consistency_check.py:467-476` 读取）：

   ```jsonc
   "panel": { "prefix": "【", "max_lines": 4, "forbid": ["..."] }   // 没有 enabled 开关
   ```

   `panel` 的启用方式是**该 dict 存在**，没有 `enabled`；上限键名是 `max_lines`。
   更糟的是 `config_problems` 只校验**已知键的类型**，未知键 `max_entries` **不报错**。
   实测：给 10 行面板条目 + `{enabled:true, max_entries:4}` → **零发现**；
   换成 `{max_lines:4}` → 立刻报「面板条目行数 10 > 上限 4」。

   → 若照清单示例写进模板，**面板防线会继续保持静默关闭，而人以为已经开了**。
   这正是清单自己在 P0-3 批评的那种失败。

3. **`extra_discipline` 在本仓零读取。** 全仓 grep 只命中 `content/templates/AGENTS.template.md:217`
   的一个模板占位符 `{{extra_discipline}}`，没有任何脚本读它。
   照清单去写这个键 = 写死配置。

4. **证据来源错**。清单引 `docs/15-未测项与盲区清单.md` 作为「新书防线全关」的证据，
   但 `docs/15` 通篇引用的是**旧 kit** 的实体：`brief.py:140`、`doctor.py`、`init_book`、
   `scripts/`、`hooks/`、`audit.py`、`selftest.py`、`sync.py`——**这些在本仓都不存在**。
   而且 `docs/15` 第 **147 行**的整改状态表已把该条标为
   `| 2 | 新书默认＝防线全关 | ✅ 已修 | init_book 写入可用默认… |`。
   清单**只摘了问题陈述（第 33-38 行），没读同一份文件的状态表**。

   > 真正的结论反而更有价值：旧 kit 的 `init_book` 修过这个问题，
   > 而迁到本仓后由 `apps/cli/src/commands/init.ts` 接手，**这个修复在迁移中丢了**。
   > 这不是「从来没做」，是**回归**。

5. 验证命令同样缺 `--dir`（见 P0-1 第 3 条）。
