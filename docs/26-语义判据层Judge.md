# 26 · 语义判据层 Judge（B-11）

> 对应 BACKLOG B-11 / v0.2 M11 / docs/24 P0-1。落地于 `4605a54`。
> 本文记的是**为什么这么做**与**哪里偏离了蓝图**，不是 API 手册。

## 1. 为什么需要它

机械判据到顶之后只剩一层：**词面匹配**。

真书《高武》上 `novel hooks` 是 `specs 60 / unwritten 26 / checked 19 / skipped 15 / failed 16`，
而 16 条红灯里 ch-11、ch-21 是已知假红——细纲标的是**意图**，正文写的是**变体**
（「前天刚校准」→「前天刚由省局技术处做过深度校准」）。词面匹配再拧，也只能降级为只读线索
（docs/23 §2 的裁定）。

结果是一种**看起来安全、实际空洞**的状态：门禁保证了「绿不是伪造的」，
但「绿」本身不代表写得好。Judge 补的就是这层：用 LLM 按**意图**判，
判据是 J1 蓝图契约 / J2 章末钩子 / J3 连续性。

## 2. 三条纪律（写死在实现里，改之前先想清楚）

### 纪律 1：证据引句必须逐字命中，命不中即降 `unsure`

没有这条，模型可以随口说「第 5 段与设定冲突」而根本不存在那段。
那比没有判据**更坏**：它把编出来的结论写进了看起来可信的报告。

- 命中范围按判据自己的 `quoteScope`：
  - `chapter`（J2/J3）= 只认正文。这两类判的是「正文里哪句有问题」，必须能指出那一句。
  - `any`（J1）= 正文或参考材料都算。**「细纲要点没写到」这类缺席断言没有正文句子可引**，
    只能引细纲里那句要求；若连细纲里都没有，照样降 unsure。
- 去空白兜底比对一次：LLM 复述引句时常改换行/缩进，那不是幻觉，不该判 not-found。
  两关都过不了才判 `not-found`。
- **只降不丢**：原判留在 `rawVerdict`，理由里标「⚠️ 疑幻觉」，供人工核对。
  静默丢弃会让人以为「模型没提这条」。

### 纪律 2：`unsure` 既不算通过、也不算拦截

单独进 `manual` 人工清单。**模型漏回一条同样按 unsure 处理**——
「没判」不许变成「没问题」。这与项目既有的
「查不到与查了没问题必须形状不同」是同一条规矩的第四次应用。

### 纪律 3：未声明判据 → 显式报错，绝不静默通过

判据定义在 `.soloent/judges/<id>.md`（**作者可改**），`book.json` 的 `judges.enabled`
显式声明启用哪些——沿用 rules 的「不扫目录、不递归」纪律。

一个「没声明 = 0 条 finding = 看起来全绿」的实现，正是本项目反复在治的静默失效。
所以 `loadJudges` 在未声明时抛 `JudgesNotDeclared`，声明了但文件不存在时抛 `JudgeDefMissing`。

## 3. 一处对蓝图的偏离：不写 `gateStatus`，改落 `state/judge.json`

**v0.2 M11 写的是「结果写入 gateStatus，同样绑 checkedMtimeMs」。本实现没有照做。**

理由两条，任一条都足够：

1. **会被静默冲掉。** `applyGateResult` 是**全量覆写**——机械 gates 每跑一次，
   就把每一章的 `gateStatus` 重新写一遍（未命中 findings 的章置 `clean`）。
   判据结论若并进去，下一次 `novel gates --write` 就把它抹了。
   这是「写进去了但会丢」，比不写更坏：报告上看得见，实际早没了。
2. **会丢信息。** M10.5 明说 Gates 与 Judge **不查同一项**。把两者压成一个 `worst`
   之后，「这章是机械判据没过还是语义判据没过」就再也分不出来了。

所以判据结论单独落 `state/judge.json`，每章 `{worst, count, manual, checkedAt, checkedMtimeMs, judges}`，
**过期清扫语义与 `gateStatus` 完全一致**（mtime 不符即作废该章条目）——
「内容变了结论就失效」这条防线不能少。

两者**怎么合起来判「能否提交」**是 B-12 的事，那时才有真正的合并语义需求。
现在合并等于凭空造一个没人验证过的口径。→ 已登记 B-63 待作者裁定。

## 4. CLI 与配置

```
novel judge --book <书目录> --scaffold     # 落默认三份判据（已存在的不覆盖）
novel judge --book <书目录> --list         # 看已声明/未声明
novel judge --book <书目录> --chapter 5 [--advisory] [--write]
novel judge --book <书目录> --status       # 只读结论（含过期清扫）
```

`book.json`：

```json
"judges": { "enabled": ["j1-blueprint", "j2-hook", "j3-continuity"] }
```

- `fail` 默认记 **「中等」**（拦截级）；`--advisory` 降为 **「提示」**（只报告）。
  **为什么留这个模式**：语义判据的假红率尚未标定。在拿到真书数据之前就让它拦人，
  会重演 `hook_check` 那条路——16 条假红把闸门变成噪音，最后只能整项降级。
- 一次 LLM 调用跑完所有已声明判据（省 token，且让模型能跨判据对照）；温度 0.2；
  JSON 解析失败重试 1 次（v0.2 M7.5），仍败返回 `parse` 失败，**不吞错**。

## 5. 验证

- 单测 15 项（`packages/core/test/judges.test.ts`）。判定核心抽成纯函数
  `evaluateCriteria`，让「引句命不中就降级」这条纪律**能脱离模型被测**——
  否则这条最重要的防线只能靠真调 LLM 验证，等于没有回归网。
- 端到端用**本地假 LLM 端点**（不起真模型）验过：真引句 → finding；
  编造的引句 → 降 `unsure` 且标「疑幻觉」；落盘；改章后结论自动作废。
- 全量 86 项通过。
