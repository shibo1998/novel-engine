## 2. 三处与任务书结论不同的地方

审查报告对下面三点的判断需要修正（其余各条的机制描述均属实）：

**① F16「writeState 是不是原子写」——是。**
`packages/core/src/state.ts` 的 `writeState` 一直是「写 `story.json.tmp` → rename」，
不存在半写 JSON 窗口。前端「数据闪一下没了」的风险不成立。
另外 `/state` 的成本是「读 1 个 `story.json` + 每章 1 次 stat」，**不是**逐章读正文；
唯一会退化成整书重读的是 `story.json` 缺失时走 `rebuildState`，属冷启动路径。
因此**没有**加 TTL 缓存：该文件自陈「无状态——每次请求现读，不缓存任何东西」，
为一条毫秒级路径引入「可能读到旧数据」这个新失败类不划算。
真正修的是重复：过闸写链原先跑两轮全量 stat（清扫 + 回填），现在正好一轮。

**② F18「watcher 那条链跑不起来」——属实，但它一直是失败关闭。**
`kit.run_child` 对「子脚本缺失」返回 **-2 而非 0**（kit.py 里专门有一段注释讲这是
曾经的假通过坑），所以 watcher 会报错而非静默放行；只是提示词把人指向不存在的
`preflight.py`。根因也不是「少一个文件」：`preflight.py` 是 `watch_and_check.py` 在
kit 里的**同级兄弟**，迁入本仓时只搬了 `consistency_check.py + kit.py + watch_and_check.py`。
另发现一个任务书未提的真 bug：`kit.run_child` 返回的是 stdout+stderr **拼接**，
而检查器是「JSON 走 stdout、摘要走 stderr」，原代码取「最后一行」当 JSON，
在任何存活的检查器上都会解析失败——已改为逐行从后往前找「带 counts 的对象」。

**③ F19「内容层零断言」——不成立，但缺口是另一种形状。**
`check()` 有实打实的内容断言（唯一写法 / 人物越界 / 数字情报矛盾 / 时间线 / 门控词 /
锁定细节 / 黑名单 / 生僻字 / 标点风格 / 章末升华 / 超长章 / 比喻堆砌 / 面板条目 /
钩子 / 伏笔 / 句长节奏）。问题是**它们全是「不该有什么」**，一条「应该有什么」都没有
——零内容的章天然全绿。即：不是缺校验，是**断言方向单一**，与协议层那个
「查不到 = 没问题」同源、只是下沉了一层。已补空章下界与缺标题两条存在性断言。

## 3. 任务书未覆盖、本轮顺带发现并修掉的

1. `apps/server` 的 `/state` 与 `/chapter` 之外，工作区新增的 `/summarize`、`/generate`、
   `/feedback`、`PUT /chapter` 同样是写盘口子——一并纳入 F14 的写盘闸门与白名单。
2. `runGates` 的 exit 失败只回显 stderr **首行**，而检查器的配置校验错误是把缺项列在
   后续行里的，导致「哪个键写错了」被截掉。列在此处备改（未动，属独立小项）。
3. `content/templates/AGENTS.template.md`、`docs/00`–`docs/13` 等 **legacy 文档**仍通篇
   指导作者执行 `python tools/preflight.py` 与 `tools/start_watcher.ps1`，两者在本仓都不存在。
   这些文档按 README 的定位是「旧手册，保留为 legacy 参考」，故本轮只清掉了
   `watch_and_check.py` 自身 docstring 里的引用，**未批量改写 legacy 文档**——
   若要真按现状重写，是一项独立的文档迁移任务。
