## 2. 三处与任务书结论不同的地方

审查报告对下面三点的判断需要修正（其余各条的机制描述均属实）：

**① F16「writeState 是不是原子写」——是。**
`packages/core/src/state.ts` 的 `writeState` 一直是「写 `story.json.tmp` → rename」，
不存在半写 JSON 窗口。前端「数据闪一下没了」的风险不成立。
另外 `/state` 的成本是「读 1 个 `story.json` + 每章 1 次 stat」，**不是**逐章读正文；
唯一会退化成整书重读的是 `story.json` 缺失时走 `rebuildState`，属冷启动路径。
因此**没有**加 TTL 缓存。这一条不是判断，是实测（脚本造 N 章探针书后直接量 `readState`）：

| 规模 | 冷读（无 `story.json`，整书重建） | 稳态读（1 读 + N stat + 清扫） | `runGates` 全量扫描（对照） |
|---|---|---|---|
| 500 章 | 122 ms | 8 ms | 414 ms |
| 2000 章 | 445–495 ms | 23 ms | 693 ms |

面板按 5 s 轮询：稳态 8–24 ms 在噪声级；冷读最坏 495 ms 仍远小于轮询间隔，人类不可感知。
而缓存的**正确**失效判据需要对全部章 mtime 做签名（N 次 stat ≈ 稳态那一轮的成本），
等于用同样的 IO 换掉同样的 IO，还额外引入一个「可能读到旧数据」的失败类。
已有零成本替代：`novel state --book <目录> --rebuild` 落一次索引，`story.json` 此后一直在。
真正修的是重复：过闸写链原先跑两轮全量 stat（清扫 + 回填），现在正好一轮。

**② F18「watcher 那条链跑不起来」——属实，但它一直是失败关闭。**
`kit.run_child` 对「子脚本缺失」返回 **-2 而非 0**（kit.py 里专门有一段注释讲这是
曾经的假通过坑），所以 watcher 会报错而非静默放行；只是提示词把人指向不存在的
`preflight.py`。根因也不是「少一个文件」：`preflight.py` 是 `watch_and_check.py` 在
kit 里的**同级兄弟**，迁入本仓时只搬了 `consistency_check.py + kit.py + watch_and_check.py`。
另发现一个任务书未提的真 bug：`kit.run_child` 返回的是 stdout+stderr **拼接**，
而检查器是「JSON 走 stdout、摘要走 stderr」，原代码取「最后一行」当 JSON，
在任何存活的检查器上都会解析失败——已改为逐行从后往前找「带 counts 的对象」。

**③ F19「内容层零断言」——不成立，但缺口是另一种形状。**
`check()` 有实打实的内容断言（唯一写法 / 人物越界 / 数字情报矛盾 / 时间线 / 门控词 /
锁定细节 / 黑名单 / 生僻字 / 标点风格 / 章末升华 / 超长章 / 比喻堆砌 / 面板条目 /
钩子 / 伏笔 / 句长节奏）。问题是**它们全是「不该有什么」**，一条「应该有什么」都没有
——零内容的章天然全绿。即：不是缺校验，是**断言方向单一**，与协议层那个
「查不到 = 没问题」同源、只是下沉了一层。已补空章下界与缺标题两条存在性断言。

## 6. 本轮新发现并修掉（不在 F12–F20 内）：细纲来源只认按章文件

**触发**：拿真书《高武-从全校倒数第一开始加点》做只读体检时发现——
`preflight --chapter 35` 报「缺少本章细纲 `outline/ch-35.md`」，
而该书 `outline/ch-*.md` **一个都没有**（34 章全无），细纲是按卷写在一份文件里的。

**根因**：`checkChapterReadiness` 硬编码 `outline/ch-${NN}.md`，
完全不读该书 `book.json` 里**早就写着**的 `paths.outline = "outline/第一卷-垫底-细纲.md"`。
后果有两条，都不轻：
1. 每一章都会报一条**永远无法消除**的告警——按本项目自己的标准（信噪比比覆盖率重要），
   这是把整条告警通道的可用性拉低；
2. `buildPrompt` 会向模型注入「（暂无细纲）」，而卷纲就在盘上——
   等于每写一章都告诉模型「你没有细纲」。

**修法**（三级回落，`packages/core/src/readiness.ts`）：
1. 按章文件 `outline/ch-NN.md` 存在 → 用它（最具体，保持原有行为）；
2. 否则读 `book.json` 的 `paths.outline`，**从卷纲里抠出本章那一段**；
3. 抠不到 → 退化为卷级背景，并**显式说明**「这是卷级背景、没能定位到第 N 章段落」。
三级都没有才算缺细纲（此时 `outlineFile` 为空串，不再报一个不存在的路径）。

**为什么必须「抠」而不是整卷注入**：真书第一卷细纲 16 485 字节、覆盖第 1–60 章。
整段注入等于把第 1–20 章的内容当成第 35 章的细纲喂给模型——比不注入更坏，
因为模型会照着错的章写，而且看不出错。

**同批修掉的一个注入缺陷**：卷级背景原先会在「第一个章号行」处截断，
于是 `## 第一幕（1–10 章）` 会紧贴在「35 一战成名」上面被一起注入，
让模型以为第 35 章属于第一幕。现改为：卷头只在**二级及以下标题**处截断；
幕标题必须**声明的章号范围确实覆盖本章**才注入（读不出范围或覆盖不到就不给——宁缺勿乱）。

**真书验收**：第 35 章现注入「卷主题/卷任务/矛盾网/钩子约定 + `## 第三幕「选拔赛」（21–35 章）`
+ 本章那一行」，共 459 字符；`preflight` 不再报缺细纲。
测试：`packages/core/test/readiness.test.ts` 新增 5 个用例
（含「不覆盖本章的幕标题不得注入」「注入内容不得混进别的章」两条负向断言），
core 测试 32 → 38 项全绿。
